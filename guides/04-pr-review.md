# PR과 코드 리뷰 (6교시)

오늘은 코드 대신 문서를 리뷰합니다. 규칙은 코드 리뷰와 같습니다.

## PR 만들기

1. 저장소의 **Pull requests(풀 리퀘스트) → New pull request(새 PR)** 를 누릅니다.
2. **base(받는 쪽)** 는 `develop`, **compare(보내는 쪽)** 는 내 `feature` 브랜치로 고릅니다.
3. 제목에 이슈 번호를 넣습니다: `BL-01 대상 결과 화면에 AI 판정 안내 추가`
4. 양식을 채우고 **Reviewers(리뷰어)** 를 지정합니다.
5. Slack에 PR 링크를 공유합니다.

## 좋은 PR

- 이슈 하나만 다룹니다.
- 왜 바꿨는지 적습니다.
- 리뷰어가 무엇을 봐야 하는지 알려 줍니다.

## 리뷰하기

1. **Files changed(변경된 파일)** 탭을 엽니다.
2. 고칠 줄에 마우스를 올리고 **+** 를 눌러 의견을 답니다.
3. **Review changes(리뷰 제출)** 에서 하나를 고릅니다.

| 선택 | 언제 |
| --- | --- |
| Approve(승인) | 병합해도 됨 |
| Comment(의견) | 의견만 남김 |
| Request changes(변경 요청) | 고쳐야 병합할 수 있음 |

## 리뷰 규칙

| 규칙 | 좋은 예 | 나쁜 예 |
| --- | --- | --- |
| 근거를 말한다 | R-15에 문의 방법이 필요합니다 | 뭔가 빠진 것 같아요 |
| 사람이 아니라 내용을 말한다 | 이 문장은 사용자가 오해할 수 있습니다 | 왜 이렇게 쓰셨어요? |
| 고칠 방향을 제안한다 | "담당자가 다시 확인합니다"는 어떨까요? | 다시 쓰세요 |
| 꼭 고칠 것과 의견을 나눈다 | [필수] 기준값이 다릅니다 / [의견] 표현 제안 | 구분 없이 나열 |

## 병합 전 확인

- [ ] 승인을 받았다
- [ ] 충돌이 없다
- [ ] 받는 브랜치가 맞다
- [ ] 병합 후 Jira 이슈를 완료로 옮겼다
